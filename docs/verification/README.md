# 验证脚本

用 Playwright 在真实浏览器里跑，模型响应用 `page.route` 拦截，所以结果是确定的、不花钱、不联网。

## 怎么跑

```bash
# 1. 在仓库根目录起服务器（serve.py 禁用缓存，避免新旧模块混用）
python3 serve.py

# 2. 另开一个终端
NODE_PATH=$(npm root -g) node docs/verification/<脚本>.js
```

可用环境变量：`BASE`（默认 `http://localhost:8899`）、`CHROME`（Chromium 可执行文件路径）、`SHOT_DIR`（截图目录）。

## 各脚本守着什么

| 脚本 | 守着的东西 |
|---|---|
| `pipeline-test.js` | 最初的验收路径：导入未标注文件后**逐步点击**标注（不是一次性生成），无篇章关系与从句从属两条分支都走一遍，每个跑过的 skill 都必须出现在树上；并行格式的空白文档必须一次给出全部技能槽 |
| `format-switch-test.js` | **文档和标注方式是两回事**：在「精修」下导入不许被强行掰成 UMR；换方式换的是方式、不是文档（id、句子、文档下拉都不动）；两种方式各自的成果互不覆盖，来回切换后原样还在；导出会把没在屏幕上的那一种也带上；文件里带着标注的文档仍然按它自己的方式打开 |
| `csp-test.js` | 在 `script-src 'self'`（**没有** unsafe-eval，**也没有** unsafe-inline）之下必须完整启动、**0 条 CSP 违规**——这就是"eval 报错不是本页面造成的"的证据；同时验证 boot guard 能记录并转述它没造成的违规 |
| `devtools-issues-test.js` | 直接订阅浏览器 Issues 面板（CDP Audits），**必须一条都没有**——表单控件缺 id/name、label 没绑定控件、废弃 API、CSP 违规都会被抓到 |
| `wiki-demo.js` | 拿一篇维基百科文本从零标到底，然后**回查每一步到底有没有覆盖原文**，逐句给出严格口径 / 后端宽松口径两个覆盖率和"真正丢失"的词 |
| `skill-update-test.js` | 走完「异议 → 记入问题 → 审核保留 → 反思 → 应用」整条路之后，那条规则**真的进了下一次 prompt**（标准只有一条：新 prompt 里字面包含它），且刷新后仍在；中途每一步都不许提前改到技能文件 |
| `replay-test.js` | replay 模式查得到录制数据；查不到时**说对是哪一种情况**（文档没录制 vs. 当年导出漏了这一步） |
| `i18n-threads-test.js` | 语言**下拉菜单**（不是按钮）：至少三种语言、每种用自己的文字写、双向切换干净、刷新后保持；文件式 locale（日语）缺的键回落**英文**而不是中文；每个节点的对话彼此独立，且能互相跳转 |
| `boot-banner-test.js` | 用 `file://` 打开时，红色横幅必须出现并说清原因（否则页面看着能用、其实一行 JS 都没跑）；用 HTTP 打开时横幅消失且语言按钮真的能切 |
| `boot-diagnosis-test.js` | boot 失败时横幅必须**说清是什么问题**：模块执行报错要打印真实消息+文件行号；模块 404 要点名是哪个文件；缓存造成的新旧模块混用要报出缺的那个导出名；数据文件卡住要说卡在哪一步，且 15 秒后报超时 |
| `wiring-test.js` | 少一个界面元素时，**只能**让那一个按钮失灵，其余（尤其是语言切换）照常工作，并在日志里点名说是哪个元素 |
| `provider-test.js` | 发出去的请求长什么样、一次发几个：OpenAI 必须用 `max_completion_tokens`（旧的 `max_tokens` 被推理模型直接 400）、要有默认模型、被模型拒绝的参数要自动丢掉重试一次；Anthropic 的长指令块要标成可缓存；互不依赖的位置必须**并发**发出，总耗时明显小于串行之和 |
| `authoring-test.js` | 三件必须能改的东西：①文件导入方法（内置读法读树库是乱码 → 换成 CoNLL-U 读法后句子/token/列都对；每种格式各存各的；坏的读法要回退而不是让文件打不开）②技能说明可以直接改写、保存后就是下一次真正发出去的内容、能还原 ③参考实现要和说明并排显示；④精修链的 `validate` 是**真的在跑代码**，不发 prompt |
| `export-test.js` | 导出的文件到底对不对：标一遍、人工改一处、再用另一种方法标同一篇，然后导出、重新打开对比 —— 人工修改、没在屏幕上的那种方法的成果、每次调用的记录都要在；`_trace` 这种内部索引不许漏出去；Map 不许序列化成 `{}` |
| `edit-commit-test.js` | 人工修改默认用 Penman 编辑；保存后「标注后文件」**立刻**变；还原能回到模型原始输出；修改不会串到别的句子；手打的 `<np: 短语>` 连空格一起活着回来；每条边在编辑框里**只出现一次**（占位符和填了它的子节点是同一条边） |
| `edit-structure-test.js` | 人工修改会改**树的形状**，不只是值：已解析节点也要显示 `:condition` 这类关系标签（右边有、左边没有就是 bug）；把 `<>` 写成 `(x / concept)` 那一行就该消失；手写一个 `<np: …>` 就该多一行、能点、点了真的跑；还原要把形状也还原回去 |
| `reflection-test.js` | **技能不会因为一次修改就更新**：人工修改 / 重跑 / 换技能 / 对话异议都只记成问题；审核前拒绝反思；被忽略的问题不参与；反思读的是保留下来的**整批**；即使反思出了条款，也要人再按一次「应用」才进提示词 |
| `refine-chain-test.js` | 串联式 refine 格式：步骤严格按序（后面的步骤点不动）、每一步的输入确实是上一步的整张图、成品图始终是最新一步的产物、从中间重跑会作废后面的步骤、某一步返回坏图必须被标记且**不能毁掉上一步的好图** |
| `live-effect-test.js` | 「当场生效」按**下一次调用真正收到什么**来判定：人工改完 concept 后，下游那个以上游输出为输入的步骤（reentrancy 的节点清单）必须看到改后的值；skill 修订接受后必须立刻显示在该技能的面板上，并进到下一次 prompt，撤销同样立刻 |
| `i18n-leak-test.js` | 英文模式下走一遍全流程，屏幕上**一个中文字都不应该出现**（语言按钮和中文语料标题按 DOM 排除，不靠字符串白名单） |

失败判定：多数脚本以退出码报告（非 0 即失败），并逐条打印 `✓` / `✖`；`wiki-demo.js` 与 `skill-update-test.js` 打印中文断言，看输出即可。所有脚本都会统计控制台错误和 `pageerror`，**期望是 0**。

> 这些脚本**都在仓库里**，不是临时文件。这是有代价换来的教训：早期几个测试只存在临时目录里，容器一重置就没了。
