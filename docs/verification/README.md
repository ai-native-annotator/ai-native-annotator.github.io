# 验证脚本

用 Playwright 在真实浏览器里跑。模型（Jev、Haiku 等）的回答用 `page.route` 拦截（`_skillparse-mocks.js`），所以结果是确定的、不花钱；页面要从 CDN 加载 Pyodide，这一点需要联网。

## 怎么跑

```bash
npm install
npx playwright install chromium

npm run test:browser                          # 启动无缓存服务器，依次运行全部脚本
npm run test:browser -- skillparse-test.js    # 只跑一个
npm run test:browser -- --list                # 列出脚本
```

runner 默认用本项目安装的 Playwright 的 Chromium，并给自己启动的服务器分配空闲端口。环境变量：`BASE`（目标地址）、`CHROME`（换一个 Chromium）。已经自己启动了服务器就加 `--no-server`。

## 各脚本守着什么

| 脚本                         | 守着的东西                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `skillparse-test.js`         | 整个循环走一遍：Python 启动、中文流程打开；一句话一步一步跑，每一步确认之后才有下一步；只有 sent_type 问 Jev，agent 步骤拿到 system 和 skill.md、真的调用工具、经 `final_result` 回答；图画出来、点框跳到写它的那一步；人工修改一步；右栏把修改变成 skill 的改动并验证；调上下文窗口；导出 `.umr`；换到英文流程                                                                                                                                                                                                                                    |
| `skillparse-fullrun-test.js` | 导入的各种格式（`.txt` 按行、自动分句，`.umr` 重新标注、载入已有标注），wave 0 整句生成再按规则转换，乌兹别克语流程，暂存的进度和导入的文档刷新后还在                                                                                                                                                                                                                                                                                                                                                                                              |
| `boot-recover-test.js`       | 网站更新后浏览器还留着旧脚本（主机允许缓存 10 分钟），新旧模块混用、页面起不来：页面自己绕过缓存把脚本重新取一遍再刷新，然后正常启动（这件事在线上发生过）                                                                                                                                                                                                                                                                                                                                                                                         |
| `modes-test.js`              | 专家模式：点一下按钮才整篇生成，生成时有进度条、已用时间和估计的剩余时间；写在前一句的文档级关系归到后一句；关系用词显示，能改、删、加；同一个对话既改本句（回车应用）也改全文（每条标句号、点了跳转）；图上直接改概念和关系标签；长文档分几次写，每次带上前面所有句子，漏了的句子再问一次；前面某句有没做完的步骤时照样能加文档级关系；重新生成一句；回车下一句；看不到步骤编号，手动模式里步骤都在。学徒模式：不提前生成，一次一步，有讲解、回答、查了什么、交给下一步什么；回车确认并跑下一步；手改、Tab 提示重跑；做完一句换下一句，再进文档级 |
| `github-test.js`             | GitHub 流程，GitHub 是脚本里的替身（一个仓库、分支、文件、pull request）：token 是一项设置；标注者打开仓库里的 `.txt`、标注、提交成 pull request（有写权限直接开分支，没有就 fork，再提交是更新同一个）；审定人找到两份标注，一致性（Smatch F、文档级 F、一致句数），一致的句子直接采用；有差别的句子并排、差别行有标记、列出差别、模型讲差别；取一份、换另一份、到专家模式手改；合并进主分支（adjudicate 分支和它自己的 pull request，正文写明比较和决定），关闭各位的 pull request；刷新后进度还在                                               |

`live-models.js` 不在默认运行之列（要花钱）：`OPENROUTER_KEY=… npm run test:live` 用真的模型经 OpenRouter 跑几步（wave 1 用 OpenAI 的模型整句生成，sent_type 问 Jev，下一步分别用 Anthropic 和 OpenAI 的模型带工具跑），打印每个请求的模型、`tool_choice` 和状态，出错时打印服务返回的内容。

每个脚本逐条打印 `✓` / `✖`，有失败就以非 0 退出；也统计控制台错误和 `pageerror`，期望是 0。
