# 验证脚本

用 Playwright 在真实浏览器里跑。模型（Jev、Haiku 等）的回答用 `page.route` 拦截（`_skillparse-mocks.js`），所以结果是确定的、不花钱；页面要从 CDN 加载 Pyodide，这一点需要联网。

## 怎么跑

```bash
npm install
npx playwright install chromium

npm run test:browser                          # 启动无缓存服务器，依次运行全部脚本
npm run test:browser -- skillparse-test.js    # 只跑一个
npm run test:browser -- --list                # 列出脚本
```

runner 默认用本项目安装的 Playwright 的 Chromium，并给自己启动的服务器分配空闲端口。环境变量：`BASE`（目标地址）、`CHROME`（换一个 Chromium）。已经自己启动了服务器就加 `--no-server`。

## 各脚本守着什么

| 脚本                         | 守着的东西                                                                                                                                                                                                                                                                                                      |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `skillparse-test.js`         | 整个循环走一遍：Python 启动、中文流程打开；一句话一步一步跑，每一步确认之后才有下一步；只有 sent_type 问 Jev，agent 步骤拿到 system 和 skill.md、真的调用工具、经 `final_result` 回答；图画出来、点框跳到写它的那一步；人工修改一步；右栏把修改变成 skill 的改动并验证；调上下文窗口；导出 `.umr`；换到英文流程 |
| `skillparse-fullrun-test.js` | 导入的各种格式（`.txt` 按行、自动分句，`.umr` 重新标注、载入已有标注），wave 0 整句生成再按规则转换，乌兹别克语流程，暂存的进度和导入的文档刷新后还在                                                                                                                                                           |

每个脚本逐条打印 `✓` / `✖`，有失败就以非 0 退出；也统计控制台错误和 `pageerror`，期望是 0。
