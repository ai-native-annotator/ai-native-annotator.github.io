# SkillParse 工作台：功能一览

在浏览器里一步步做 UMR 标注：SkillParseUMR 的标注流程直接在网页里运行，不需要服务器。模型的 API key 只存在你这台电脑的浏览器里。

## 1. 流程和三波

- **三种语言**：中文（web-zh）、英文（web-en）、乌兹别克语（web-uz）。打开文档时按文档语言自动选择。
- **wave 1 · generate**（可选）：模型一次写出整句的图、对齐和文档级标注，再自动拆成后面两波的步骤。
- **wave 2 · sentence**：一步一步建句级图，每一步一个 skill。
- **wave 3 · document**：文档级标注，分 modal（模态）、temporal（时间）、coref（共指）三个并列的步骤（1、2、3），互不影响。
- 打开文档时停在 wave 1；不想用它也可以，切到 wave 2 一步步标。

## 2. 文档

- 自带几篇样例文档（中文、英文、乌兹别克语）。
- **导入…**：
  - 纯文本：一行一句，或整段自动分句；
  - .umr 文件：只取句子重新标，或连同标注一起载入（载入的每一步都算已确认，可以再改）；
  - 语言可以自动判断，也可以自己选（乌兹别克语要选）。
- 导入的文档和标注进度都保存在浏览器里；刷新页面后会问你是否恢复。

## 3. wave 1：整句生成

- **umr_generate**：参考前五句已经生成的结果，一次写出这一句的图（penman）、对齐和文档级标注。默认模型 GPT-6.1 Sol，可换成 Opus 5.5。
- **convert**：检查生成的图（能不能解析、对齐有没有越界、文档级标注里的变量在不在），确认后自动拆成 wave 2 和 wave 3 的步骤，标「生成」。
- **▶▶ 生成整篇**：每一句依次生成、转换；遇到出错的句子就停下。
- **乌兹别克语先分词**：第一步是 tokenizer（规则），不只按空格切：标点、引号单独切开，2023-yil、kecha-yu、kelasizmi? 这类写法会拆开，复合词和后缀不拆。
- 没有模型跑过的步骤（wave 1 生成的、从 .umr 载入的），系统会替每个带义项号的概念模拟一次 PropBank 查询，在「工具调用」页能看到。

## 4. wave 2：一步一步建图

- **步骤树**：sent_type 判断这一段是什么（问 Jev），再交给 discourse、predicate、np_phrase 或 special_entity，一直到 stop 叶子。
- **每一步跑完要确认**，同一句的下一步才会开始：
  - **Enter**：确认并跑下一步；
  - **Tab**：带提示重跑（写一句话告诉模型哪里不对）；
  - **直接修改**：自己改输出。下面那些输入没变的步骤会保留，指向这一步的文档级关系也会自动跟着改。
- **页签**：
  - 输出（Penman 格式）；
  - 输入与提示词（模型实际拿到的内容）；
  - 问答（Jev 的封闭问题和回答）；
  - 工具调用（看模型查了什么，也可以自己填参数调用工具）；
  - 图（点节点跳到写它的那一步，悬停可以看对齐的字）；
  - UMR 文本（变量可以点）。
- **所有句子：下一步**：每句各跑下一步。
- **模型**：顶栏切换模型：Anthropic 的 Haiku、Sonnet、Opus、Fable，OpenAI 的 GPT-6 Luna、GPT-6.1 Terra、GPT-6.1 Sol、GPT-6 Astra，各自从便宜到强。在 wave 1 选的是整句生成用的，其他波选的是 agent 步骤用的。
- **计时器**：每句、每波分开计时。
- **四栏可以折叠**：上下文、Skill 栏、生成内容、AI 四栏，标题右边的 ⟨ 把这一栏收成一条竖条，点竖条展开；其他栏自动变宽。

## 5. wave 3：文档级

- **modal**：由规则生成（按 umr-tool 的转换办法），不调用模型。
- **temporal、coref**：由模型标，只看这一句，以及它和前文的关系。
- 节点显示成 `<node: 原文 / 概念>`，旁边有这一句和前文节点的对照表。
- 改其中一步，其他步骤不受影响；句子的图改了以后，指向它的关系会跟着更新。

## 6. 右栏

- **改这一句的图**：
  1. 写一句评论，说哪里要改（可以用变量名、原文的词或步骤编号）。
  2. 模型读这一句的步骤树和变量对照表，提出一组改动：新增或删除节点、改概念、新增或删除关系、改属性（aspect、modstr 等）。它需要时会自己查各个 skill 的写法、PropBank、金标和指南。
  3. 在「UMR 文本」和「图」上看彩色预览：**绿色**是新增，**红色划掉**是删除，**橙色**是修改。
  4. 逐条勾选，点「执行」。执行后自动拆回步骤（一直到叶子，不用再手动新增）；没改到的步骤保留原样，文档级关系跟着走。
- **反思这一步**（针对选中的那一步）：
  - ① 自己改 skill；
  - ② 先改对输出，让 AI 找出 skill 里的问题；
  - ③ 说哪里错了，让 AI 改 skill。
  - AI 提出的修改以对比形式显示，勾选了才会应用，改完可以重跑验证。
- 右栏每一栏用哪个 skill、给模型什么内容、用哪个模型，都在 registry.yaml 的 `user_panel` 里配置。

## 7. skill 和工具

- **左栏**列出每个 skill（包括右栏用的）和它的文件：可以在线阅读、编辑、保存为新版本、对比版本、恢复原版。保存后，下一次运行就用新版本。
- **模型可用的工具**（结果都是排好版的 Markdown）：
  - propbank_lookup：中英文 PropBank 的全部 roleset 和例句；
  - search_annotations：搜金标标注；
  - search_guidelines：搜 UMR 指南。

## 8. 导出

- **导出 .umr**：可以自动补全对齐，也可以保持原样。
- **训练数据（JSONL）**：每一步的输入和输出；可以只导出已确认的步骤，也可以全部导出。
- **工作记录（JSON）**，以及**改过的 skill 文件**。

## 9. 设置（⚙）

分四块，每块都能折叠：
- **API key**：OpenRouter、Anthropic、OpenAI、TypeSafe（Jev），只存在这个浏览器里。
- **模型**：这里不用选，模型在顶栏选。按填了哪些 key 自动决定走哪个服务：有 Anthropic / OpenAI 自己的 key 就直连，没有就经 OpenRouter；这里能看到各项现在用的模型、走哪里，以及哪些模型现在能用。
- **Jev**：经 TypeSafe 直连还是经 OpenRouter。
- **其他**：同时调用模型的数量（并发数）。
- 界面语言：顶栏的 EN / 中文按钮。
